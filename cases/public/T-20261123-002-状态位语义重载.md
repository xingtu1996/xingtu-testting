# T-20261123-002 · 一个 ✅ 两种含义：状态位语义重载

- 状态：`verified`（自有坏例索引，已脱敏改写）
- 核对日期：2026-11-23

## 问题是什么

问"今天发了什么"，四个数据源给出四种答案。表面是数据不同步，本质是**同一列的状态位既表示"计划"又被读成"已完成"**——判据本身有歧义，怎么查都查不出一致结论。

## 背景与约束

- 触发场景：一份排期里同时存在"计划发布"和"已发布"两种状态需求。
- 约束：多个来源并存（日历 / 周计划 / 日志 / 后台实况），且部分来源自称"唯一事实源"却未必回写。

## 当时怎么判断 / 怎么做

叠加了两层问题：

1. **派生字段靠推断而非计算**：文档里的星期标签整体错一天，因为生成时手推而非实测日期。一个基础字段错了，基于它的所有排期都偏。
2. **状态位语义重载**：日志里"首发 ✅"既想表达"计划首发"，又容易被读成"已发布"。同一符号承载两种互斥含义，下游无法可靠判读。
3. **事实源没有强制回写**：日历自称唯一源，但生成排期后没回写当天行，导致它自己就是旧的。

结果：同一个日期，日历说 A、周计划说 B、日志说 A 且标记首发、后台实况是 B。四源对账才能拿到真相。

## 证据

- 来源：维护者自有坏例索引一条真实对账记录，已去除文章标题、日期、版本号、文件名等全部实体。
- 本机实测：按"先实测日期 + 四源对账 + 语义分离"整改后，同类追问一次答准。

## 结论与适用边界

- **结论成立的前提**：多个数据源 + 同一字段承载多种语义 + 派生字段可推断。
- **核心判据**：**状态位必须语义单一**——计划态和完成态分列，绝不共用符号。一个字段一旦能读出两种意思，它就不再是判据，只是噪音。
- **配套做法**：派生字段（星期/间隔/窗口）一律计算不推断；自称"唯一事实源"的东西必须有强制回写动作，否则它只是"某个来源"；跨源追问先对账再作答。
- **换场景**：单数据源、状态语义单一时，这套开销可省；但只要出现"到底算不算完成"的争论，第一反应就该查语义是否重载。
